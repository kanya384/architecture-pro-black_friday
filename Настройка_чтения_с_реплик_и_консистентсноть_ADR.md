### <a name="_b7urdng99y53"></a>**Название задачи: Настройка чтения с реплик и консистентность**
### <a name="_hjk0fkfyohdk"></a>**Автор: Кушу Л.Р.**
### <a name="_uanumrh8zrui"></a>**Дата:21.05.2026**
### <a name="_3bfxc9a45514"></a>**Проблематика**
Для коллекций products и orders и carts нужо определить какие из операций могут читать из secondary реплик, а какие только
из primary и указать какая задержка репликаций допустима для операций на secondary. При расчете надо опираться на требования
о консистентности данных, чаастоту обновлений и бизнес-логику.

### <a name="_u8xz25hbrgql"></a>**Решение**

**Products**:

- *Частые обновления остатков при покупках*

  В данном случае нужна запись остатков на primary, так как актуальные остатки будут только на этой шарде.

- *Поиск товаров по категориям и фильтрация по диапазону цен*  

    Можно осуществлять на Secondary шардах, нужно постараться добиться минимальной задержки репликации, 
    чтобы минимизировать поисковую выдачу товаров которые только закончились и улучшить тем самым пользовательский опыт.
- *Описание товара на странице продукта*

    Запрос описания товара можно осуществлять на Secondary шардах, задержка репликации в данном случае не имеет большой
    роли, так как описание меняется редко и не оказывает сильного влияния на потребителей

**Orders**:

- *Быстрое создание заказов с одновременным списанием остатков*
    
    Только primary шарда и операцию производить в транзакции чтобы гарантировать ACID

- *Поиск истории заказов конкретного пользователя*

  Можно осуществлять на Secondary шардах, если пользователь недавно создал новый заказ то отправлять его на primary шарду.
  Такой поведение можно настроить средствами MongoDb

- *Отображение статуса заказа*

  Можно осуществлять на Secondary шардах, как правило не требует ежесекундного обновления, поэтому адекватная задержка в репликации не 
 критична


**Carts**:
- *Создание корзины, когда заходит гость или новый пользователь*
- *Добавление или замена товара в корзине*
- *Слияние гостевой корзины в пользовательскую, если пользователь залогинится*:
  прочитать гостевую { session_id, status:"active" };
  добавить её items в корзину { user_id, status:"active" };
  отметить гостевую как abandoned.
- *Удаление товара из корзины*
- *Отметка корзины как заказанной*

Это все операции записи производятся на primary шардах, слияние корзин нужно производить в транзакции чтобы гарантировать ACID 

- *Получение текущей корзины по фильтру { session_id, status:"active" } или { user_id, status:"active" }*:

    Можно читать с реплик, но если пользователь недавно произвел какаую-то операцию с корнзиной, то отправлять его на primary 
    шарду
